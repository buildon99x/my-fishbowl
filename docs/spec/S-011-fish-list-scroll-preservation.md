# S-011 물고기 목록 스크롤 위치 보존

## 상태

- 상태: ready
- 구현 여부: done
- 검증 여부: tested

## 목표

- 사용자가 `물고기 목록` 패널을 스크롤한 뒤 버튼, 선택, 게이지, 편집 컨트롤을 조작해도 목록의 스크롤 위치가 초기화되지 않도록 한다.
- 목록 내부 조작으로 전체 앱이 리렌더링되더라도 사용자가 보던 목록 위치를 유지한다.

## 범위

- 포함:
  - 물고기 목록 스크롤 컨테이너 식별
  - 앱 리렌더 전 스크롤 위치 캡처
  - 앱 리렌더 후 스크롤 위치 복원
  - 물고기 선택, 표시/숨김, 편집 열기, 게이지 조작, 반전/초기화 버튼 조작 시 위치 유지
- 제외:
  - 목록 가상화
  - 목록 항목 자동 스크롤 이동
  - 브라우저 세션을 넘어선 스크롤 위치 영구 저장

## 사용 흐름

1. 사용자가 여러 물고기가 있는 `물고기 목록`을 아래로 스크롤한다.
2. 사용자가 현재 보이는 항목의 버튼 또는 편집 게이지를 조작한다.
3. 앱은 상태를 갱신하고 화면을 다시 렌더링한다.
4. 새로 렌더링된 물고기 목록은 리렌더 전과 같은 `scrollTop` 값을 복원한다.
5. 사용자는 목록이 처음으로 튀지 않고 같은 위치에서 계속 조작할 수 있다.

## UI/상태 요구사항

- 필요한 화면 요소:
  - `data-fish-list`가 붙은 물고기 목록 스크롤 컨테이너
- 필요한 상태:
  - `appState.fishListScrollTop`: 마지막으로 캡처한 물고기 목록 스크롤 위치
- 오류 또는 빈 상태:
  - 물고기가 없거나 목록 DOM이 없으면 스크롤 캡처/복원은 아무 동작도 하지 않는다.
  - 목록 접힘 상태에서는 스크롤 복원을 시도하지 않아도 된다.

## 구현 메모

- 관련 파일:
  - `src/main.js`
- `renderApp()`은 루트 DOM을 교체하기 전에 `captureFishListScroll(root, appState)`를 호출한다.
- 루트 DOM 교체 후 `restoreFishListScroll(root, appState)`를 호출해 새 `.fish-list` 노드에 이전 `scrollTop`을 적용한다.
- 이 기능은 물고기 목록 DOM 교체로 인한 UI 위치 손실을 막는 UI 상태 보존 로직이며, 물고기 데이터 저장 형식에는 영향을 주지 않는다.
